RSMC - WHAT EACH VERSION DID
============================

One or two lines per version, newest first. This file is the short form; CHANGELOG.md is
the detailed history and carries the reasoning. BOTH ARE MAINTAINED - every version bump
gets an entry in each.

The rule is adopted from rstweaks, where it was learned the hard way: versions 0.2.18
through 0.2.46 of that mod were never written down and the detail is unrecoverable.

0.1.3
-----
  /rsmc info prints the mod version first on every path, and how many patterns the structure
  holds (used of capacity) - the number that makes RS's crafting calculator more expensive for
  the whole network.

0.1.2
-----
  canPlaceItem was 16.3% of the server thread: insertItem calls it per slot and the filter
  parses the pattern, so one shift-click validated the same pattern 54 times. Memoised per
  stack (by identity - ItemStack has no equals). Profile also showed the predicted hot path,
  the once-a-second refresh, is 0.18% - and that 22.8% belongs to Step Crafter, not us.

0.1.1
-----
  Fixed the multi-second freeze when shift-clicking patterns in: setPattern invalidates RS's
  crafting indexes, and every insert re-pushed EVERY slot. Now tracks dirty slots per storage
  block as a BitSet and pushes only those. Missing patterns are most likely the 78->54 nerf
  truncating old saves - if it recurs in a post-0.0.25 world, that is a different bug.

0.1.0
-----
  IT CRAFTS. The milestone the versioning rule reserved the minor digit for. Also halved the
  refresh cost: the Controller found the structure and StructurePatterns.of found it again, so
  the box was scanned twice a second. Remaining known cost is that once-a-second O(volume)
  refresh - the poll #3 removes.

0.0.25
-----
  Pattern Storage nerfed 78 -> 54 patterns. Also fits the screen better: 54 is six rows of nine,
  so a storage block fills the grid exactly. One constant, everything else derives from it.

0.0.24
-----
  Crafts stalled because nothing ever called node.doWork(). RS ticks a pattern provider's own
  block entity to step its tasks (NetworkNodeBlockEntityTicker); our ticker only refreshed the
  screen. The node joined, took patterns, reported speed, appeared in the preview - and never
  stepped. tickNode() now runs every tick.

0.0.23
-----
  Copied the manager properly. THE shift-click bug: RS adds player inventory slots in the menu
  CONSTRUCTOR as well as in resized(), which only runs client-side - so the server menu had no
  player slots and every click index was wrong. Also imageWidth is 193, not 176 (the extra
  width IS the scrollbar track, hence the missing background), and the title is a
  TextMarquee(title, 70) so it scrolls instead of overlapping. No structure rebuild needed.

0.0.22
-----
  Slots use RS's Sprites.SLOT via blitSprite, the same call the Autocrafter Manager makes,
  instead of two hand-drawn rectangles - which is what the black grid lines were. Fifth time
  the answer has been "use the RS class".

0.0.21
-----
  Fixes the server crash 0.0.20 shipped with. A container CANNOT be removed while its block
  stands - RS rescans from a neighbour and requires it to be absent, but the capability keeps
  answering. Node resizing now drops and rebuilds the block entity next tick instead. Also
  fixed: writing patterns past the node's size, and an endless rebuild loop from joining the
  network before the structure was read.

0.0.20
-----
  The pattern provider node (#2 last step): Controller hosts a real PatternProviderNetworkNode
  with the structure's patterns, speed and energy. Node rebuilds when capacity changes - free,
  because patterns live in the blocks. Patterns pushed only when a version sum changes.
  Plus /rsmc info now says whether the held item is accepted, since an encoded pattern cannot
  be built in a gametest.

0.0.19
-----
  Shift-clicking a non-pattern in only LOOKED like it worked: the server always refused, the
  client predicted it. Client menu now uses RS's PatternInventory instead of a SimpleContainer
  so both sides filter identically. Found that a BLANK pattern is refused too - RS wants an
  encoded one - now asserted.

0.0.18
-----
  Deleted three more hand-rolled things RS already provides: addPlayerInventory(), the
  TransferManager for shift-click (one line, and the same path every RS screen uses), and the
  playerSlots list they made necessary. Assessed copying the Autocrafter Manager wholesale:
  feasible, maps one group per Pattern Storage block, worth doing after crafting works.

0.0.17
-----
  Patterns render as their output: implement RS's PatternOutputRenderingScreen, and copy
  containsPattern INCLUDING its reference equality, which is what keeps the same pattern in
  your inventory rendering as a pattern. Lifted renderSlotContents and added RS's
  SearchIconWidget. Standing instruction from Wraith: reuse RS classes wherever possible -
  reimplementing what RS solves has cost four bugs in two versions.

0.0.16
-----
  Four fixes from the first real look at the screen: player inventory floated mid-panel
  (resized() must position it - a stretching screen has no fixed height), pattern area was
  blank (RS's row texture is plain; renderRows has to draw the wells), scrollbar did nothing
  (setup belongs in init(rows), not init()), and the title is now MultiBlock Crafter.

0.0.15
-----
  Pattern screen rebuilt on RS's AbstractStretchingScreen + SearchFieldWidget instead of
  imitating it: stretches to screen height, real scrollbar, same chrome. Deep coupling to RS
  internals is how addons are written - Step Crafter extends four RS base classes and mixins
  into AbstractGridScreen. Texture is RS's autocrafter_manager.png unmodified, since the blit
  offsets are theirs to match.

0.0.14
-----
  The pattern screen opens: right-click ANY block in the structure. Search field, every pattern
  slot, scrolling - both done by moving slots, which is safe because positions are client-side
  and clicks travel as indices. A block outside a structure explains the failure in chat
  instead of opening an empty window. Needed an access transformer: Slot.x/y are final in
  1.21.1 and a filtered list re-flows horizontally, which RS's setSlotY helper cannot do.
  Chrome is plain for now; matching the Autocrafter Manager exactly is a second pass.

0.0.13
-----
  StructurePatterns: every pattern slot in a structure as one container, ordered by position so
  server and client agree and a chunk reload cannot shuffle a player's patterns. Interior-only
  scan. Tested across a storage boundary, where the slot arithmetic would fail silently.

0.0.12
-----
  Pattern Storage holds 78 patterns, saved and dropped on break, using RS's own PatternInventory
  so validity is theirs. Drops handled in onRemove like RS's container blocks - a loot table
  cannot drop contents. Tested against both silent losses: save/load round trip and the drop
  list. GUI design recorded on #4: RS's Autocrafter Manager is built from classes we already
  compile against, so the screen can match it rather than approximate it.

0.0.11
-----
  Gametest for the one untested branch: a structure cabled to an RS Creative Controller reads
  ACTIVE. That is where the last bug hid, and it is what the pattern provider will gate on -
  get it wrong and the crafter is silently dead while everything else passes. Confirmed by
  removing the power source and watching it fail.

0.0.10
-----
  Screen lit regardless of being connected: RS makes a network for a LONE container, so
  getNetwork() != null tests nothing. Now uses RS's own rule - energy required, and network
  stored >= this structure's draw - which forced the energy model to become real
  (StructurePower wired in; a CPU costs exactly its tier weight). Gametest tightened from
  "not UNFORMED" to "INACTIVE exactly" and confirmed against the old code.

0.0.9
-----
  Controller gets its own three faces, generated from casing.png by
  tools/GenerateControllerTextures.java. The old placeholder was RS's real grid front and got
  mistaken for a Grid in game - looking like our own block is a correctness property. RS grid
  textures removed; three plain orientable models. assetCheck covers all three faces and
  models (71).

0.0.8
-----
  /rsmc info reports the server's own screen state, including when the structure does not form,
  so a stale client can be told apart from a wrong answer. Added a gametest reproducing the
  reported stuck-screen steps - it passes, so the server path is correct; kept as a regression
  pin for when #3 replaces the poll.

0.0.7
-----
  Active screen uses RS's default light blue rather than the blue dye colour. Filed #8 for the
  full colour system, which is NOT cosmetic in RS - ColoredConnectionStrategy refuses
  connections between differently-coloured blocks.

0.0.6
-----
  Controller screen has three states - grey unformed, dark formed-but-unplugged, blue live -
  as a layered cutout model over RS's grid textures, no image editing. Adds the mod's only
  ticker, one per structure, once a second. Plus /rsmc info: look at any rsmc block and it
  explains the structure, or names the failure, its position and what that position wanted.
  Both exist because "nothing happened" was indistinguishable from "built it wrong".

0.0.5
-----
  Cable to any face again. The per-tick cost 0.0.4 was avoiding does not exist: RS ticks nodes
  only via a BlockEntityTicker the block opts into (ours declares none), and ServerListener.tick
  is a queued-action drain that never iterates nodes. Frame and Casing carry a connection relay
  BE - no ticker, no NBT, no energy. Controller keeps the provider node, GUI and energy. No
  port block needed.

0.0.4
-----
  Controller block: replaces one Casing on a wall, exactly one, never an edge. It is now the
  ONLY block with a block entity or a network node - 2,168 of each down to 1 on a 16^3, since
  the shell only needed them to be reachable by cable. Trade: the cable must touch the
  Controller. Result.controllerPos is the derived host. New failures NO_CONTROLLER and
  TOO_MANY_CONTROLLERS (reports the second one). 30 shape checks, 65 asset checks.

0.0.3
-----
  The structure joins an RS network (#2, step 1/4). Every shell block hosts a node container,
  because RS walks the graph OUTGOING-ONLY - a cable probes the position next to it, so one
  node at the corner would connect only at the corner. Found by reading
  ConnectionProviderImpl, not guessed. The lookup is a NeoForge capability; missing it is
  silent. Gametest asks the way RS asks, confirmed to fail without the registration.

0.0.2
-----
  Creative tab pinned immediately after Refined Storage's via withTabsAfter, instead of being
  appended to the end of ~28 pages of tabs. Tab id read from RefinedStorageApi, not hardcoded.

0.0.1
-----
  The whole of the first day. Originally numbered 0.1.0 - 0.4.1 (five versions in an
  afternoon); renumbered because nothing had been published and the number overstated a
  scaffold with no working crafter. CHANGELOG.md has the five stages in order.

  Structure detection and the throughput model, both free of Minecraft types. Shell-and-core
  shape following Reborn Storage: Frame edges, Casing walls, CPU + Pattern Storage interior,
  3x3x4 minimum DERIVED from the interior requirement. No controller object and no assembly
  state machine - the structure is derived from the world, patterns live in the blocks. Seven
  blocks with items, creative tab, loot tables, models and the mineable tag. shapeCheck (24)
  + assetCheck (57) headless, 4 gametests.
